# Voice Calling / IVR — Setup Guide

Everything in the voice stack is **already built and probed**. This document is
only about the credentials and the tunnel, which are account-level and cannot be
generated by the application.

## What already exists (no code needed)

| Layer | Where |
|-------|-------|
| Provider abstraction (4 providers) | `app/Services/AI/VoiceProviderManager.php` |
| Call orchestration | `app/Services/Voice/VoiceCallService.php` |
| Admin controllers (13) | AICalling, CRMVoice, SIMCalling, VoiceAgentAdmin, VoiceCallScheduler, VoiceUpload, Telecalling, VoiceBot, … |
| Webhook receiver | `app/Http/Controllers/Api/TwilioVoiceWebhookController.php` |
| DB | `ai_calling_agents` (6), `ai_calling_intents` (12), `ai_call_sessions` (26), `ai_call_extracted_leads` (3), `ai_voice_models`, `telecaller_*` |
| LLM for the conversation | Same chain as chat: Groq `whisper-large-v3` (STT) + `orpheus` (TTS), Gemini for Hindi |

The pipeline has already run end-to-end: 26 call sessions produced 3
auto-extracted leads.

## Step 1 — pick ONE provider

| Provider | India voice quality | Cost | Notes |
|----------|--------------------|------|-------|
| **Exotel** | good | ~₹0.30/min | Most common in India, easy trial |
| **Twilio** | excellent | ~$0.014/min | Best programmatic docs, global |
| **Plivo** | good | cheaper than Twilio | Good support |
| **Knowlarity** | best Hindi | mid | Indian, Hindi-first TTS |

**Recommendation: Exotel** for an India-first real-estate deployment.

## Step 2 — credentials

Where to paste them (do NOT edit PHP files):

- Voice provider keys → `/admin/service-configs` → group **Twilio** (or the group
  matching your provider). This screen stores them in
  `service_configs` with masking and an audit trail.
- STT / TTS preference → `/admin/ai-settings` → *Voice Pipeline Engines*.
- LLM keys (already set: Groq / OpenRouter / Gemini) → `/admin/ai-settings`.

## Step 3 — public tunnel (Ngrok)

Voice providers must call **back** into your machine. `localhost` is not
reachable from their servers, so a tunnel is required.

```powershell
# install once
winget install --id ngrok.ngrok -e
ngrok config add-authtoken <YOUR_TOKEN>      # from https://dashboard.ngrok.com

# run it (leave the window open)
ngrok http 80
```

You will see something like:

```
Forwarding  https://a1b2-c3d4.ngrok-free.app -> http://localhost:80
```

## Step 4 — tell the provider

In the Exotel/Twilio/Plivo dashboard, set the **call status / recording webhook**
to:

```
https://a1b2-c3d4.ngrok-free.app/api/voice/webhook/twilio
```

(the exact path is the one your provider shows; the receiver is
`Api/TwilioVoiceWebhookController`)

For **outbound** campaign callbacks use:

```
https://a1b2-c3d4.ngrok-free.app/api/voice/callback
```

## Step 5 — verify

1. Admin → `/admin/ai-calling` (or `/admin/ai/voice-calling`) → run a **test call**
   to a number you control.
2. Watch for a new row in `ai_call_sessions`.
3. If the AI qualified the call, a row appears in `ai_call_extracted_leads`.
4. Transcripts land in `voice_call_logs`.

## Production note

Ngrok free tier gives a **changing** hostname, so it is fine for testing but not
for production. When you move to the live domain, replace the ngrok URL with your
own HTTPS domain and set the webhook there once. Nothing in the code changes —
only the URL configured at the provider.
